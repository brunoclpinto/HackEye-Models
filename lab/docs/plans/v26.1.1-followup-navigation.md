# v26.1.1 follow-up: previous/next navigation that wraps, no thumbnail carousel

Status: **approved 2026-10-27** (the user said "plan, execute"). No version bump: the user said this is a fix within
v26.1.1. Worker: Sonnet (frontend). Planning, review and integration: Opus.

User request: "i expressed myself wrong, navigation of images is next and previous, no carroussel thumbs. when i said
carroussel i meant infinite navigation, so last next goes to first and first previous goes to last. don't bump version
for this fix".

## Change
- **Browse group (top, permanent, collapsible):** the filter bar as before, plus one navigation row:
  - `← Prev`, the position (`i / N` within the filter) and `Next →`;
  - the tag buttons ok, fix, drop and todo;
  - the frame count.
  - **The thumbnail carousel is removed**, along with its first/last buttons and `Home`/`End`.
- **Wrap-around:** Next on the last frame of the filter goes to the first; Prev on the first goes to the last.
  - It works in the frontend: when `GET /api/frames/{stem}` returns `next: null` (or `prev: null`), the frontend fetches
    the first frame (`offset=0&limit=1`) or the last one (`offset=total-1&limit=1`) with the same filter.
  - A filter with one frame stays on it. An empty filter shows "no frames".
- **Keys:** `←`/`→` and `N`/`P` step with wrap-around and autosave when dirty. `Shift+1`–`4` tag. Digits pick recent classes.
- **When a filter changes:** if the current frame still matches, it stays; otherwise the view goes to the first frame of the
  new filter. (This is unchanged.)
- **Unchanged:** thumbnails are still used for the Rules samples (`thumb.jpg`), and the backend API doesn't change.
