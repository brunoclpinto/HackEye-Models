# v26.1.3: no Work group, groups at full height, Detected/Undetected classes with counts, selected class only when picked

Status: **shipped 2026-10-29** on branch `lab26.1` (the user said "go for it"). Worker: Sonnet (frontend). Planning,
review and integration: Opus.

User request: "drop work group, the subgroups are enough; groups and subgroups are never scrollable inline, just occupy
the height they need to occupy; classes divided into 2 parallel subgroups detected (classes found in selected image) and
undetected (classes not found in selected image); classes should have the amount of detections in front of name like
the class merge group; love the selected color and class next to search bar but should only be there if a class is
actually selected and only a selected class."

## 1. Drop the Work group
- Remove the `section.grp[data-gid="work"]` wrapper and its header (`#workTitle`). The three panes
  (`#pane-edit`, `#pane-taxonomy`, `#pane-rules`) become direct children of `#page`, after the Image group, and keep
  their sub-groups (Classes, Tools, Protect, View, Frame / Classes, Map builder, Save-export / Rule, Result).
- `app.js` no longer sets `#workTitle`. The active tab is still shown by the tab bar.
- A stored `lab.grp.work` state is simply ignored.

## 2. No inline scrolling in groups
- No group or sub-group body has its own scroll area: remove `max-height` / `overflow` from `.pk-list`, `#tTable`,
  `#tGroups` (desktop and phone rules) and drop the `.scroll` class from them. They grow to their content; the page
  (`#page`) is the only vertical scroller.
- The taxonomy table's sticky header now sticks to the page scroller (`#page`), which is fine.
- Not groups, so unchanged: the job log `pre.log` and dialogs/help overlays. On phones the taxonomy table may still
  scroll **sideways** if it's wider than the screen (no vertical inline scroll).

## 3. Edit > Classes: Detected and Undetected
- The Classes sub-group holds the picker head (§5) and then **two side-by-side sub-groups**, both collapsible
  (persisted like every group):
  - **Detected** (`data-gid="edit-detected"`, header count = number of classes): classes with at least one pixel in
    the open frame, as a flat list of chips sorted by detections, most first (ties by name).
  - **Undetected** (`data-gid="edit-undetected"`, header count): every other class, grouped by `hier` in the existing
    collapsible hier groups (gid `hier-<hier>`, collapsed by default), classes in taxonomy order.
  - Side by side on desktop (flex wrap, each `flex: 1 1 320px`), stacked at phone width.
- Re-partitioned when a frame opens and after every edit that is committed to history (brush stroke end, region,
  lasso, SAM apply, Enter relabel, undo, redo, revert, save), so a class painted in moves to Detected and a class
  painted out moves to Undetected. Search filters both lists; a list or hier group with no match hides.
- The old "absent" styling and the presence-based collapse of hier groups go away (the split replaces them).

## 4. Detection counts on chips
- Each chip reads `<swatch> <name> <count>` in Detected, the count in the same muted mono style as the merge-group
  card's "N classes" (`.muted.mono`). Undetected chips show no number (they're all 0).
- **A detection is an item**, the same thing Inspect selects: a 4-connected region of one class. The count is the
  number of such regions of that class in the frame (no minimum size). Tooltip adds the pixel total:
  `<raw name> (<id>) - <n> detections, <px> px` plus the existing click / right-click / double-click help.
- Computed client-side on the frame's class grid (one labelling pass, one Uint32Array of 1280x720; target < 60 ms;
  recomputed only on the events listed in §3, never per stroke move).
- Exposed for tests: `window.__lab.state().classCounts` = `{<id>: {items, px}}` for detected classes.

## 5. Selected class next to the search bar, only when a class is selected
- **No class is active on page load** (`picker.active = null`; recents and other stored state don't auto-select).
  Clicking a chip, a recent, a digit key `1-9`, or `X` (swap, when a secondary exists) selects one. Clicking the active
  chip again, or `Esc` in the search box when it is empty, clears it.
- The picker head is: search box, then — **only while a class is selected** — the swatch and `<name> (<id>)` of that
  one class (`data-testid="active-class"`, `hidden` otherwise). Nothing else in the head.
- The "Erase to" secondary class box and the recents buttons move out of the head into the **Tools** sub-group (after
  the brush shape select). Behaviour unchanged (right-click a chip = secondary, `X` swaps, `1-9` recents).
- Painting tools with no active class (brush, region, lasso, SAM apply, Enter relabel) don't change pixels and show
  one toast "Pick a class first". Erase still uses the secondary class. Inspect works without a class.
- The image-header `selection-label` (Inspect selection) is unchanged.

## 6. Tests
- **E2E updates:** tests that paint must select a class first (they already pick a tool explicitly). Remove asserts on
  `group-work` / `#workTitle`.
- **New E2E (`test_classes.py`):**
  - no `active-class` shown on load; after clicking a chip it's shown with that class's name; clicking it again hides it;
  - Detected holds exactly the classes present in the fixture frame's mask (checked against the PNG on disk), Undetected
    the rest, and both together cover the taxonomy once;
  - the chip count equals the 4-connected region count from a Python labelling of the fixture mask
    (`scipy.ndimage.label` with 4-connectivity, or a small BFS if scipy isn't in the image);
  - painting a new undetected class into the frame moves it to Detected with count 1; undo moves it back;
  - painting with no class selected changes no pixels and shows the toast;
  - no element inside `#page` other than `#page` itself has a vertical scrollbar (`scrollHeight > clientHeight` with
    `overflow-y` auto/scroll) on Edit and Taxonomy;
  - the Work group is gone (`[data-gid=work]` count 0) and the panes sit directly under `#page`.
- Unit tests unchanged (backend untouched).
