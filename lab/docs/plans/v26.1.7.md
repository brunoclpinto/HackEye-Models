# v26.1.7: Erase means unlabeled, Outline draws over the mask, a visible Grid, unique class names

Status: **shipped 2026-10-31** in b2656d2 (the user said "go for it"). Worker: Sonnet. Planning, review and integration: Opus.

User request: "out of the blue erase started behaving like brush. outline is adding and removing mask. grid no longer
works. make sure classes are correctly assigned and names are displayed correctly. go for it"

## Findings (Opus, 2026-10-31)
- **Erase:** Erase paints the hidden *secondary* class, which defaults to the first taxonomy class, **animal bird (id 0)**.
  v26.1.6 removed the visible "Erase to" box, so nothing showed what Erase paints. The user's 7 strokes on
  `Chest-center-0001_000000` today painted about 57k px of animal bird over sky, building, road, car and sidewalk. The edit
  log stores erase strokes as `brush` (`endEdit(E.tool === "erase" ? "brush" : ...)`).
- **Wrong names:** the same bug makes "animal bird" appear in Detected and on the Inspect labels. Separately, 8 classes
  show their raw Vistas id as their name (ids 35, 45, 50, 54-58, e.g. `marking--discrete--crosswalk-zebra`):
  `_short_name` (last two parts) collides between `marking--…` and `marking-only--…`, and the collision fallback is the
  full raw name.
- **Outline:** outline mode replaces the colour fill with thin 1 px edge pixels drawn in the same mask layer, so pressing O
  makes the mask disappear and pressing it again brings it back.
- **Grid:** it renders in headless Chromium at 32× with no class selected. It only appears from 8× and is a faint
  `rgba(255,255,255,.22)` line, so at the zoom levels the user works at, toggling it shows nothing.

## 1. Erase = void unlabeled
- `E` **Erase** paints **void unlabeled** (`raw_name` `void--unlabeled`, id 123 in the 124-class taxonomy; look it up by
  raw name, fall back to 255 "ignore" when it's missing). Void classes are ignored in training, so erased pixels mean
  "no label".
- The secondary class is removed entirely: `picker.secondary`, the `sec` chip style, right-click on a chip (back to the
  browser default, or do nothing), and `X` swap. Erase no longer depends on any hidden state.
- Erase needs no active class. Protect still applies.
- The tool button title, the status bar and the help say "Erase to void unlabeled (E)". The status bar shows
  `Erase 8r → void unlabeled`.
- The edit log records erase strokes as `erase` (not `brush`).

## 2. Outline draws over the mask
- The **Mask** button (M) alone shows or hides the colour fill. **Outline** (O) adds class-boundary lines on top of
  whatever the mask shows; it never removes the fill.
- Boundary lines go in a separate layer (`lineC`), drawn at full opacity after the mask, in the class colour, for every
  pixel whose 4-neighbour has a different class (same rule as now: all four neighbours when a class is selected, right and
  bottom otherwise; keep it consistent: use the all-four rule in both cases so lines are symmetric).
- With a class selected, the fill and the lines cover only that class (as now).
- Outline works with Mask off (lines only), and the opacity slider affects only the fill.
- Dirty-rect updates still repaint only the touched rect (+1 px border) for both layers.

## 3. Grid that is visible
- The pixel grid shows from **4×** (was 8×).
- Line contrast: draw each line twice, a dark `rgba(0,0,0,.35)` then a light `rgba(255,255,255,.35)` offset by 1 device
  pixel, or an equivalent that stays visible over white, black and saturated class colours.
- When Grid is turned on below 4×, toast "Grid shows from 4×" once.
- Verify it with a class selected, with Outline on, after pan, and at devicePixelRatio 1 and 2 (Chromium and WebKit). Fix
  whatever fails.

## 4. Unique, readable class names
- `_short_name` collision rule (`datasets/vistas/conversion/vistas_config.py` and its caller): on a collision, use the
  **first and last** parts (`marking crosswalk-zebra`, `marking-only crosswalk-zebra`, `marking dashed`,
  `marking-only dashed`, …) instead of the raw name; if that still collides, fall back to all parts joined by spaces.
  Names must be unique, never contain `--`.
- Regenerate `taxonomies/vistas124.json` names. Ids, raw names, colours and hier don't change, and merge maps use raw
  names, so they are unaffected.
- Patch the master's `taxonomy.json` (`~/media/hackeye-models/datasets/HackEye26.1-124/taxonomy.json`) and
  `HackEye26.1-124.yaml` `names:` for those 8 ids **only where the stored name still equals the raw name** (never overwrite
  a name the user changed). Back both files up first into the scratchpad.
- The released `.pt` models keep their embedded names (not touched).
- Unit test: every name in `vistas124.json` is unique and has no `--`.
